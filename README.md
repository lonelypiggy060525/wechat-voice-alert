# 微信语音提醒（WeChat Voice Alert）

把微信那声难听的提示音换成你选的音效，顺便把「谁发的、说了什么」念出来；吵到一半按快捷键就能打断。

- **提示音**：6 个内置音效；也可以选自己的音频，wav / mp3 / wma 直接播，**m4a / aac / flac / ogg 会自动用 ffmpeg 转成 mp3 缓存**（首次约 0.7 秒，之后秒开）；音量独立可调
- **音效库**：你加过的音频会记在列表里（`config.json` 的 `custom_sounds`），下次启动还在，随时切回去，不用重新找文件
- **界面**：侧边栏 + 卡片式分页（提示音 / 语音播报 / 提醒范围 / 快捷键 / 最近消息），改动自动保存
- **语音播报**：默认 `{sender}说：{content}`，可改模板、调语速、**调播报音量**（与提示音音量分开）；多条消息**排队播报**，念完一条再念下一条，不会互相打断
- **长消息读全文**：会话列表的预览只放得下十几个字；预览被截断时（文字占满列宽），程序会点开那个会话，读出**最新气泡的完整文字**再播报。代价：该会话会被微信标记为已读、并排到列表最前面（可以关掉这个选项，只读预览）
- **发音人**：6 个微软在线神经语音（晓晓 / 晓伊 / 云希 / 云健 / 云扬 / 云夏，接近真人）+ 本地离线 SAPI；断网时自动退回离线
- **提醒范围**：名单里每个联系人一个持久开关（点第一列切换 ☑/☐），名单外的人按「默认提醒」处理；改动约 0.5 秒后自动写盘，重启不变
- **打断**：默认 `Ctrl+Alt+Q`，随时掐断播报
- **常驻托盘**：关窗口不退出，右键托盘可暂停 / 停止播报 / 退出
- **开机自启**：勾一下就写入 `HKCU\...\Run`

## 原理（为什么是读屏幕）

这台机器上是微信 **4.2.0.13**。实测：

- 界面是 Qt 自绘（窗口类 `Qt51514QWindowIcon`，内部 `MMUIRenderSubWindow`），UI Automation 控件树只有 3 个空节点，读不到任何会话；
- 本地消息库是加密的（不是 SQLite 文件头），4.2 也拿不到解密密钥；
- 收到消息**不会**推送 Windows Toast（通知中心里从来没有微信的记录，注册表也没有它的通知通道），不弹自有弹窗，只闪任务栏 + 播它自己的声音。

所以本程序走的是「读屏幕上微信自己的会话列表」这条路：

1. 每 0.6 s 用 `PrintWindow` 抓一次微信主窗口（**被其他窗口挡住也抓得到**，不需要前置）；
2. 对左侧会话列做轻量指纹，**只在画面变化时才 OCR**（空闲约 1% CPU）；
3. 红色未读徽标 + OCR 结果决定「哪个会话来了新消息」；只有带未读徽标的行才播报，所以你自己发出去的消息不会触发；
4. OCR 用离线模型 RapidOCR（中文识别准确率远高于 Windows 自带 OCR），不联网。
5. 需要长消息全文时，用 `PostMessage` 在窗口内「点」一下那个会话（不移动鼠标、不抢焦点），OCR 右侧气泡区，再取最下面那一块文字；先核对会话标题，避免读错人。

全程不注入微信进程、不读它的内存、不改它的文件。

## 使用前提（重要）

**微信窗口不能被最小化。** 最小化后窗口不再绘制，抓不到画面，也就收不到提醒。三种处理方式：

- **隐身模式（推荐）**：勾选后程序把微信窗口挪到屏幕外——屏幕上看不到它，但它没被最小化，读屏照常工作。
  **点一下任务栏里的微信图标，它就会回到屏幕中央**；再点 × 或最小化，它又自动挪走（保持读屏）。
  也可以点界面里的「调回微信」。
- 或者放在后台、被别的窗口挡住就行，不用理它；
- 或者勾选「微信被最小化时自动还原到后台」，程序会把它还原（不抢焦点，并且压到其他窗口下面，不会跳到最前面），代价是微信会时不时自己冒出来。

## 下载

到 [Releases](https://github.com/lonelypiggy060525/wechat-voice-alert/releases) 下载 `WeChatVoiceAlert.exe`，
双击就能用，不用装 Python。因为没做代码签名，Windows 可能弹「已保护你的电脑」——
点「更多信息 → 仍要运行」即可。

首次启动会解压运行时（单文件打包，约 5–10 秒），之后每次启动也要 3–5 秒；
想更快就用下面的源码方式启动。

## 从源码运行

```bat
uv venv --python 3.11 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.venv\Scripts\pythonw.exe app.py
```

需要 ffmpeg 才能用 m4a/flac 这类格式（程序会自动在 PATH / winget 目录里找）。

## 运行

双击 `启动.vbs`（无控制台窗口）。或：

```bat
.venv\Scripts\pythonw.exe app.py
```

关窗口 = 收进托盘；退出用托盘右键菜单。重复启动只会把已有窗口叫到前面（单实例）。

## 配置

`%APPDATA%\WeChatVoiceAlert\config.json`；播报记录（含命中的名单规则）在同目录 `last_messages.log`。

**所有设置改动都会自动保存**（约 0.5 秒后写盘），包括提示音、音量、语速、模板、名单开关和快捷键；
「保存并应用」只是立刻再写一次。名单存在 `contact_rules` 里：名字 → `true` 提醒 / `false` 不提醒。

## 性能占用（实测）

| 项目 | 数值 |
| --- | --- |
| 空闲 CPU | ≈0%（20 秒采样 CPU 时间 0.00 秒，只有每 0.6 秒一次的窗口截图 + 像素指纹） |
| 空闲内存 | ≈150 MB（主要是 RapidOCR 的中文模型常驻） |
| 来一条消息 | 触发一次 OCR：约 0.9 秒，占用约 2 个核；之后立刻回到 0 |
| 磁盘 | 配置和日志几 KB；只有用 m4a 等格式时才在 `%APPDATA%\WeChatVoiceAlert\sounds` 存一份转换缓存 |
| 网络 | 只在用在线神经语音时：每条消息几十 KB |

空闲时它只是每 0.6 秒截一张窗口图算个像素指纹（几毫秒），没有新消息就不会跑 OCR。

## 已知限制

- **在线发音需要联网**：每次合成约 0.5–1.5 秒（先响提示音、再说话），断网会自动改用离线的 Huihui 音色
- 名单匹配忽略 emoji、空格和标点：OCR 读不出 emoji，`🐷小猪` 在屏幕上只剩 `小猪`，所以直接粘带 emoji 的原名也能匹配；纯 emoji 的昵称（如 `🐷`）没有可匹配的文字，匹配不到（保存时会提示）
- 只读会话列表：拿到的是一行预览（约 14 个字），长消息会被截断；图片/表情/语音没有正文，会念成「发来一条消息」
- 开「朗读完整内容」后，长消息会读最新气泡的全文（含换行的多行气泡），但**更早的几条历史消息不读**；读的时候会把该会话标为已读
- 微信把同一会话的连续消息合并时，只播报最后一条的预览
- 会话太多时列表会滚动，屏外的会话看不到未读
- 微信关掉窗口 / 退出登录时不工作（界面顶部会显示状态）
- 隐身模式只能「挪走」窗口，不能把它收进托盘：微信本身被最小化或右键退到托盘后，仍需「自动还原」才能继续读

## 文件

| 文件 | 作用 |
| --- | --- |
| `app.py` | 主程序：界面、托盘、播报调度、过滤、快捷键 |
| `wechat_list.py` | 抓微信窗口 → 未读徽标检测 → OCR → 解析会话行 |
| `tts_engine.py` | SAPI 语音（独立线程，可随时打断） |
| `sound_player.py` | MCI 播放 wav/mp3，可随时停止 |
| `hotkey.py` | `RegisterHotKey` 全局快捷键 |
| `config.py` | 配置读写 |
| `gen_sounds.py` | 生成内置音效（numpy 合成） |
| `notif_watcher.py` | 窗口 / 焦点判断等 Win32 工具函数 |
| `dev/` | 开发期探测脚本（抓弹窗、试 OCR、量 CPU），平时不用管 |
